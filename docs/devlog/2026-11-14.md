## 晚间补充：两个界面 bug

1. **画布偏右、右侧被裁**：原来用 `window.innerWidth/Height` 算缩放，
   预览面板报回的尺寸比可视区大，导致按错误基准居中。
   改成 `getBoundingClientRect()` + `visualViewport` 取最小值，
   并用「绝对定位 + 负 margin」钉住画布中心。
2. **敌人血条不显示数字**：`.bar-fill.enemy` 的 `enemy` 类名和敌人容器的 `.enemy`
   （带 `z-index: 2`）撞了，填充层被抬到文字上方。改名 `enemy-fill` 解决。
   **教训：单类名修饰符一律带前缀**，不要用 `enemy`、`active`、`done` 这种裸词。

顺带加了 hash 深链：`#/levels` 直接进关卡选择，`#/battle/7` 直接进第 7 关。

## 深夜：把反应判定从「查表」换成「规则引擎」

用户实测反馈：手牌多了界面溢出；**Zn + CuSO₄、H₂S + KMnO₄ 被判为不反应**。

根因是判定完全靠手写反应表，表里没有的配对一律拒绝。改成三层：

1. 手写反应表优先（带现象、教材出处、陷阱提示）
2. 规则引擎兜底：拆阴阳离子 → 金属活动性 / 溶解性表 / 酸碱规律推断产物
3. 系数交给通用配平器暴力求解（1..8 搜索，5 项以内 3 万组，几十毫秒）

新增 `src/engine/chem.ts`（离子表、溶解性、分类、7 条反应规则、配平器）与
`scripts/chem-check.ts`（46 条正反例回归测试）。

效果：第 1 关可打出的反应从 11 条涨到 25 条，第 3 关从 8 条涨到 28 条。

### 踩到的坑

- 配平搜索里我跳过了「系数全为 1」的情况，结果 Zn+CuSO₄、CuO+H₂SO₄
  这些最标准的方程式全被判为无解。**最简情况一定要在搜索范围内。**
- 手牌无上限，浪费回合也照常抽 2 张，牌越攒越多把界面撑爆。
  加 `HAND_LIMIT = 8` + 卡牌 flex 收缩 + 横向滚动兜底。
